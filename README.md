# Dating Profile Auditor

Полноценный учебный ML‑продукт, который анализирует био для дейтинга и помогает переписать их так, чтобы первое впечатление было теплее и конкретнее. Проект включает генерацию/разметку данных, обучение трансформера, правила для диагностик, модуль переформулировок и веб‑интерфейс на Streamlit c русским UX по умолчанию и переключателем на английский.

## Возможности
- Мульти-лейбл классификация тона и стиля (`friendly`, `confident`, `arrogant`, `sincere`, `humorous`, `cliche`, `aggressive`, `awkward_or_cringe`) на основе трансформера.
- Диагностика клише и red flags (слишком короткие тексты, требования, негатив, эмодзи и т.д.).
- Прозрачный скор первого впечатления (0–100) с объяснением.
- Три режима переписывания: теплее, смешнее, увереннее.
- Языковая поддержка: русский по умолчанию + английский режим; детекция языка и дружелюбные варнинги, если текст иной.
- Полностью модульный код: `src/` (инференс), `training/` (данные, обучение, оценка), `app.py` (Streamlit UI), `data/` (семплы и синтетический датасет).
- Готовность к деплою в Hugging Face Spaces (requirements + Streamlit).

## Архитектура
1. **Главный классификатор**  
   Файнтюн модели `cointegrated/rubert-tiny2` (русский мультиязычный BERT) на синтетическом датасете. Скрипт `training/train.py` использует `transformers.Trainer`, BCEWithLogitsLoss и считает Micro/Macro F1 + метрики по каждому лейблу. В проде `src/inference.py` сначала пытается загрузить обученный чекпоинт из `models/rubert_tiny2_profile_classifier`, а при его отсутствии применяет fallback на sentence-transformer-прототипы, чтобы сервис работал «из коробки».

2. **Диагностический слой**  
   `src/heuristics.py` запускает правила поверх текста: длина, эмодзи, многократные `!!!`, негативные или требовательные формулировки, списки типовых клише (для RU и EN). Каждая диагностика прокидывается в скоринг и интерфейс.

3. **Переписывание**  
   `src/rewriting.py` реализует контролируемые переписи: очищает жёсткие конструкции и добавляет шаблоны под нужный тон. Это стабильная альтернатива тяжёлому генеративному моделированию, которую можно расширять (например, заменить на ruT5).

4. **Скоринг и объяснения**  
   `src/scoring.py` конвертирует вероятности + диагностики в итоговый балл (0–100) с простым объяснением на двух языках, подчёркивая сильные и слабые сигналы.

5. **Веб‑приложение**  
   `app.py` (Streamlit):
   - русские тексты по умолчанию, переключатель языка на сайдбаре;
   - textarea, примеры, кнопка «Анализировать»;
   - карточка score, прогресс-бары по тонам, список диагностик, объяснение, переписанные версии, дисклеймер.

## Стратегия данных и разметки
- Публичных русскоязычных датасетов био немного, поэтому используется **synthetic/weak-label** подход: `training/dataset_builder.py` комбинирует семена с заранее заданными лейблами и интентами, добавляет вариации (эмодзи, требования и т.д.), записывает `data/synthetic_profiles.csv`.
- Скрипт генерирует сотни примеров и добавляет вспомогательные признаки (`length_bucket`, `has_emoji`, `has_negative_patterns`, `has_demands`, `cliche_count`) для дальнейших анализов. Получается более разнообразный сплав дружелюбных, юморных, требовательных и кринжовых паттернов.
- README, UI и код явно подчёркивают, что это **proof-of-concept**: модель оценивает только текст и не пытается выводить личностные черты.

## Почему трансформеры и почему русский по умолчанию?
- Русские био часто содержат разговорные конструкции, смешение кириллицы, эмодзи и английских вставок. Мультиязычный BERT (`rubert-tiny2`) + sentence-transformer дают устойчивые эмбеддинги и позволяют эффективно дообучить небольшую модель, быструю для инференса.
- Продукт ориентирован на русскоязычную аудиторию курсов/университетов, поэтому все подсказки и примеры в UI — на русском, а английский служит запасным режимом. Детектор языка помогает мягко предупредить, если текст на другом языке.

## Обучение
```bash
# зависимости для инференса/приложения (на Streamlit Cloud добавьте .streamlit/runtime.txt с python-3.12)
python3 -m pip install -r requirements.txt
# добавляем пакеты для пайплайна обучения
python3 -m pip install -r requirements-train.txt
# 1) Создать/обновить синтетический датасет
python3 training/dataset_builder.py --size 400 --output_dir data
# 2) Обучить модель
python3 training/train.py \
    --dataset_path data/synthetic_profiles.csv \
    --output_dir models/rubert_tiny2_profile_classifier \
    --epochs 6 --batch_size 8 --learning_rate 4e-5
```
Артефакты (`config.json`, веса, токенизатор, thresholds) сохраняются в `models/rubert_tiny2_profile_classifier`. После этого веб‑приложение автоматически начнёт использовать обученный чекпоинт вместо fallback-классификатора.

### Оценка
```bash
python3 training/evaluate.py \
    --dataset_path data/synthetic_profiles.csv \
    --model_dir models/rubert_tiny2_profile_classifier \
    --split test
```
Скрипт выведет F1/precision/recall (macro, micro и по каждому лейблу).

## Инференс и программное API
- Главная точка входа — `src.inference.DatingProfileAuditor`.
- Метод `analyze(text, ui_language='ru')` возвращает dataclass с предсказаниями, диагностикой, rewrite-версиями и метаданными (детектированный язык, сведения о тримминге).
- Fallback-прототипы используют `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, чтобы сервис был полезен даже до дообучения.

## Локальный запуск UI
# локально или на Streamlit Cloud (зафиксировать python-3.12 в .streamlit/runtime.txt)
python3 -m pip install -r requirements.txt
streamlit run app.py
```

### "Долгий" деплой с кастомным чекпоинтом
1. Сгенерируйте свежий датасет: `python3 training/dataset_builder.py --size 800 --output_dir data`.
2. Обучите модель: `python3 training/train.py --dataset_path data/synthetic_profiles.csv --output_dir models/rubert_tiny2_profile_classifier` (параметры при необходимости подправьте).
3. (Опционально) Запустите `training/evaluate.py` для проверки метрик.
4. Загрузите содержимое `models/rubert_tiny2_profile_classifier` либо прямо в репозиторий, либо в отдельный репозиторий на Hugging Face Hub. Если используете Hub, установите переменные окружения `DPA_MODEL_REPO_ID` (и опционально `DPA_MODEL_REVISION`, `DPA_MODEL_CACHE`) — приложение скачает веса при старте и не будет откатываться к zero-shot fallback.
В интерфейсе:
1. Выберите язык UI (по умолчанию RU).
2. Нажмите на один из примеров или вставьте своё био.
3. Кликните «Анализировать» и изучите карты: score, тональность, диагностические заметки, объяснение и три альтернативы текста.

## Деплой в Hugging Face Spaces
1. Создать новый Space типа **Streamlit**, Python runtime.
2. Загрузить/закоммитить весь репозиторий (`app.py`, `requirements.txt`, `src/`, `models/` если веса уже обучены, `data/` опционально).
3. В `app.py` используется кэширование ресурсов, поэтому модель прогружается один раз.
4. При необходимости загрузки весов из huggingface hub можно указать путь/репозиторий в `src/config.py`.

## Ограничения и риски
- Синтетический датасет ≠ реальные биографии. Метрики отражают proof-of-concept качество, а не промышленный уровень.
- Переписыватель контролируемый, не генеративный: он не добавляет новых фактов, зато сохраняет стабильность. Для более творческого текста можно подключить ruT5 / mT5.
- Fallback-прототипы дают приблизительные вероятности. Для реального использования рекомендуется обязательно обучить модель на собранных или полуразмеченных данных.
- Детектор языка (`langdetect`) может ошибаться на коротких/смешанных текстах — UI предупреждает об этом.
- Инструмент анализирует только стиль текста, не делает выводов о человеке и не должен использоваться для дискриминации.

## Этические заметки
- Нет предсказания чувствительных атрибутов, только описание тона формулировок.
- В интерфейсе многоразово повторяется дисклеймер «анализируем текст, а не личность».
- Диагностики и переписывания сформулированы конструктивно, избегают токсичности и моральных оценок.

## Roadmap / что можно улучшить

3. Добавить персонифицированные подсказки, визуализацию временных изменений профиля, экспорт отчётов.
